================================================================
PROMPT — FRONTEND ANGULAR
SISTEMA ADMINISTRATIVO DE INVENTARIOS
================================================================

CONTEXTO
--------
Desarrollar el frontend completo de un sistema administrativo
de inventarios usando Angular 17+ con standalone components,
PrimeNG 17+ y TailwindCSS.

El backend ya existe y está documentado en Swagger:
http://localhost:3000/api/docs

URL base de la API: http://localhost:3000/api

3. AUTENTICACIÓN
================================================================

- Pantalla de login con campos:
    identifier  (username o email)
    password

- Al hacer login exitoso guardar en localStorage:
    token     → JWT
    usuario   → objeto con datos del usuario
    roles     → array de strings
    permisos  → array de strings

- AuthGuard: verifica token antes de cada ruta protegida

- PermissionGuard: verifica permisos específicos por ruta

- AuthInterceptor: agrega en todas las peticiones:
    Authorization: Bearer <token>

- ErrorInterceptor:
    401 → redirigir al login
    403 → mostrar mensaje de acceso denegado
    500 → mostrar toast de error

- Al expirar el token redirigir automáticamente al login

5. FORMATO DE RESPUESTAS DEL BACKEND
================================================================

Todas las respuestas del backend siguen este formato:

// Respuesta simple
interface ApiResponse<T> {
  success: boolean;
  message: string;
  data?: T;
  errors?: any[];
}

// Respuesta paginada
interface PaginatedResponse<T> {
  success: boolean;
  data: T[];
  pagination: {
    page: number;
    limit: number;
    total: number;
    totalPages: number;
  };
}

Crear un BaseApiService que:
- Use la URL base desde environment.ts
- Extraiga automáticamente data de las respuestas exitosas
- Propague los errores con el mensaje del backend

Las listas soportan estos query params:
  page=1
  limit=20
  search=texto
  (filtros específicos por módulo)

5b. ENDPOINTS ADICIONALES DISPONIBLES
================================================================

  GET  /api/estados/:modulo   → lista estados por módulo
       Módulos: BIENES, COMPRAS, VENTAS, PRESTAMOS
       Usar para cargar dropdowns de estado en formularios

  GET  /api/bienes/disponibles            → bienes con estado DISPONIBLE
  GET  /api/bienes/disponibles?id_producto=uuid → filtrado por producto
       Usar al crear un préstamo para mostrar bienes seleccionables

  POST /api/bienes/masivo                 → crear N bienes de un producto

  GET  /api/prestamos/prestatarios        → listar prestatarios
  POST /api/prestamos/prestatarios        → crear prestatario

  GET  /api/dashboard/resumen             → métricas generales
  GET  /api/dashboard/movimientos-recientes → últimos 10 movimientos
  GET  /api/dashboard/prestamos-proximos  → préstamos que vencen en 7 días

  GET  /api/reportes/prestamos/por-persona         → bienes prestados por persona
  GET  /api/reportes/prestamos/por-persona?id_prestatario=uuid

  GET  /api/movimientos  → lista general de movimientos (paginado)
       Params: page, limit, id_producto, tipo_movimiento,
               fecha_desde, fecha_hasta, usuario

6. MÓDULO DE USUARIOS
================================================================

ENDPOINTS DISPONIBLES:
  GET    /api/usuarios                    → listar (paginado)
  POST   /api/usuarios                    → crear
  GET    /api/usuarios/:id                → obtener uno
  PUT    /api/usuarios/:id                → editar
  PATCH  /api/usuarios/:id/estado         → activar/desactivar
  PATCH  /api/usuarios/:id/password       → cambiar contraseña

- Filtro por activo/inactivo

FORMULARIO CREAR/EDITAR:
- Campos: nombre, apellido, username, email,
  password (solo crear), confirmar password
- Validaciones:
    Password mínimo 8 caracteres
    Al menos 1 mayúscula
    Al menos 1 minúscula
    Al menos 1 número
    Al menos 1 carácter especial

DIALOGS:
- Asignación de roles: lista con checkboxes
- Cambio de contraseña:
    password actual
    nueva contraseña
    confirmar nueva contraseña

PERMISOS REQUERIDOS:
  USUARIO_LISTAR   → ver lista y detalle
  USUARIO_CREAR    → botón Nuevo

17. CONTROL DE PERMISOS EN EL FRONTEND
================================================================

Los permisos vienen en el array "permisos" del localStorage.

Implementar directiva:
  *hasPermission="'USUARIO_CREAR'"

Guard en rutas:
  canActivate: [PermissionGuard],
  data: { permission: 'PRODUCTO_CREAR' }

REGLA: Los elementos se OCULTAN (ngIf), no solo se deshabilitan.

LISTA COMPLETA DE PERMISOS:
  USUARIO_LISTAR        USUARIO_CREAR
  USUARIO_EDITAR        USUARIO_ELIMINAR

  para mostrar/ocultar UI
